# 実装の計画

設計は [README](../README.md)、実際のログで確かめたことは [log-check-2026-11-08.md](log-check-2026-11-08.md)。

## 全体の形

.NET 10（LTS）。Windows でしか要らないもの（写真の監視、トレイ、インストーラー）以外は OS に依らず書き、サーバーの役は Linux でも動かす。

```
src/
  Yamaori.Core/      ログの行の読み方、訪問・出会いの組み立て、時刻の直し方（OS に依らない、外のものに頼らない）
  Yamaori.Store/     SQLite（Microsoft.Data.Sqlite）。表の作成と版の上げ方
  Yamaori/           常駐プログラム（Generic Host）。ログの見張り・生のログの保存・写真・API・WebUI を載せる
  Yamaori.Import/    VAT・VRCX・CSV の取り込み
web/                 WebUI
extension/           ブラウザの拡張機能
tests/               xUnit。実際のログから作った小さな見本（名前と ID は置き換える）で確かめる
```

読み方は 2 段に分ける。

1. **行 → 出来事**: 1 行を「入った」「人が来た」「動画」などの出来事にする。出来事は「どのログの何バイト目か」を持ち、同じ行を 2 度入れない。出来事はそのまま `log_events` に残す
2. **出来事 → 記録**: 出来事を順に流して `visits`・`encounters`・`people`・`events` を作る。読み方を直したら、この段だけ全部やり直せる（生のログからは段 1 からやり直せる）

## 段階

### 1. ログを読んで DB に入れる

> 2026-11-08: できた。to-fu の 3 本のログで 8 回の訪問が入り、VRChatActivityTools の同じ期間の記録と、訪問・会った人の数（自分を除く）・動画の数が一致した。22:41 に VRChat を起こして、動いている間は訪問が「いる」として入り、閉じるとログの最後の行の時刻で閉じることを確かめた

- 行の読み方: 入った（`Joining wrld_`＋`Entering Room`）、出た（`OnLeftRoom`・`Destination fetching`・ログの最後の行）、人の出入り、本人（`post login checks for`）、動画、アバター、通知（ID で重ねない）、スクショ、VR かデスクトップか
- 時刻: ログの時刻はローカル時刻なので、読んだ PC のタイムゾーンで UTC に直す。通知の `created at` は UTC のまま
- 見張り: 新しいログに移る、書き足された分だけ読む、止めても次に続きから読む（ファイルごとに読んだ位置を DB に持つ）
- 常駐の骨組み（Generic Host）と設定のファイル
- 終わりの目安: to-fu の今の 3 本のログから、8 回の訪問が入った時刻と出た時刻つきで入り、会った人が訪問ごとに並ぶ。途中で止めて起こしても二重にならない

不確かな点: 招待の行の今の形（今回のログに出ていない。VAT の書式で読み、合わなければ生のログから読み直す）。

### 2. 生のログを残す

- `output_log_*.txt` を書き足されるそばから別の場所へ写す（手元のフォルダ。NAS は段階 4 の送り先の仕組みを使う）。閉じたログは圧縮する
- 残したログから DB を作り直すコマンド
- 終わりの目安: VRChat がログを消しても、残したログから同じ記録を作り直せる

### 3. API と WebUI

- ASP.NET Core の REST API と OpenAPI、SSE（今の出来事）、MCP（公式の C# SDK）
- メモ・日記（Markdown）を訪問・ワールド・人・日に付ける
- WebUI: 日ごとの訪問の一覧、訪問の詳細（会った人・動画・写真）、ワールド、人、メモ。スマホの幅でも使える
- 既定は `localhost` だけで待つ。外から見せる設定にしたときは認証を付ける
- WebUI は Svelte 5＋TypeScript＋Vite で作り、ビルドした静的なファイルを常駐プログラムに埋め込む。仮想 DOM の実行部分がなく軽い。部品と型で直しやすく保つ。API の型は OpenAPI から作る（openapi-typescript）

### 4. 写真と NAS

- 写真のフォルダを見張り、XMP（ワールド・撮った人・撮った時刻）を読み、撮った時刻の訪問につなぐ。写っていた候補はその時刻にいた人
- 本人は写真の大半を NAS へ移している。NAS にある写真も読んで目録に入れる（XMP がない古い写真は、ファイル名の時刻で訪問につなぐ）
- 送り先: SMB・SFTP・WebDAV。送ったあと手元を消す・N 日残す・全部残す
- 縮小した絵を作って WebUI で見せる
- 不確かな点: NAS の写真のフォルダの形（年月ごとか、どこまで遡るか）。SMB を管理者権限なしでどう書くか（Windows の共有なら UNC パスで足りる見込み）

### 5. 取り込み

- VAT の DB: 入った（インスタンスつき）・会った（名前だけ）・動画・招待・フレンド申請。出た時刻は、次に入った時刻か、その訪問で最後に会った人の時刻で閉じ、「推定」と印を付ける
- VRCX の DB（読むだけ）: `gamelog_*`、`*_friend_log_history`、`favorite_world`＋`cache_world`、`world_memos`。to-fu には入っていないので、VRCX のソースの表の定義で作り、手元の見本で確かめる
- CSV（Notion の Worlds DB など）
- ログの記録と取り込んだ記録が重なる期間は、ログを正とする

### 6. ブラウザの拡張機能

- vrchat.com のワールドのページ・一覧のページが受け取ったデータを読み、Yamaori の API へ送る（Chrome と Firefox、Manifest V3）
- まとめて開く機能（本人が押したときだけ、最大 20 件、間隔を空ける）
- 説明文の言葉から Essential Assets などを決まりで付ける
- フレンドの一覧の差: 本人が vrchat.com のフレンドの一覧を開いたとき、ページが受け取った一覧を前回と比べ、増えた人・減った人を記録する。時刻は「前に開いたときから今回までの間」と粗い。VRCX を入れずに、自分が送った申請が承諾されたことやフレンドの増減を残すため。拡張機能から API は叩かない
- 規約との関係（2026-11-08 に利用規約を読んだ。下の「規約との関係」）: 拡張機能がデータを取る部分は、ログを読むより一段グレーに寄る。どこまで入れるか、既定で何を有効にするかは本人が決める（決めることの 4）

### 7. サーバーの役

- 同じプログラムを「集めて送るだけ」で動かす設定。記録は 1 件ずつ ID を持ち、つながらない間は手元に溜めて後で送る
- サーバー側は Linux で動かす（コンテナの見本も置く）

### 8. インストーラーと winget

- 管理者権限なしで入る形（本人のフォルダに入れ、ログオン時に起こす）
- silent install（途中で何も聞かない）
- winget のマニフェスト
- MIT で公開する前に商標を確かめる

## 規約との関係

VRChat の利用規約（Effective Date: October 23, 2026、https://hello.vrchat.com/legal ）で、Yamaori に関わる条文。

- 13.2(j): VRChat が出していない「engine, software tool, agent, device, or mechanism」で、Platform に「access, search, or otherwise use」すること、または「to extract data」ことを禁じる（robot・spider・crawler・scraper・その他の自動の手段を含む）。量や、通信を増やすかどうかの区別はない
- 13.2(i): 「harvest, or mine User Content」、「access or use the Platform in a manner inconsistent with individual human usage」を禁じる
- 13.2(g)(iii): 「attempting to collect personal information about another User or third party without consent」を禁じる
- 12: スクリーンショットと動画を撮って共有することは認めている
- コミュニティガイドライン 5.8: VRChat のログイン情報を求めるサービスを作ってはいけない

文面から読める、グレーの度合いの順（法的な判断ではない）:

1. 自分の PC のログと写真を読む: VRChat 自身がログの場所を案内し、写真に XMP を入れている。Platform に触れない。いちばん強い
2. 拡張機能で、本人が押したときに今のページの情報を保存する: スクリーンショットの許可に近いが、「extract data」に当たると読める余地はある
3. 拡張機能が、本人の開いたページのデータを自動で読む（ワールドの情報の 1・2、フレンドの一覧の差）: 通信は増えないが、13.2(j) の「software tool … to extract data」に文面上は当たる。フレンドの一覧は、ほかの人の情報なので 13.2(g)(iii) にも近い
4. 拡張機能がタブをまとめて開く（ワールドの情報の 3）: 自動の手段に近づく
5. API を叩く: 13.2(j) に当たる。Yamaori は作らない（VRCX の DB を読むだけにする）

なお、会った人の名前と ID をログから記録すること自体も、13.2(g)(iii) の「ほかの人の情報を集める」に文面上は近い。VRChatActivityTools・VRCX も同じことをしており、記録は本人の手元だけに置く、という立場で扱う。
