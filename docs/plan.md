# 実装の計画

設計は [README](../README.md)、実際のログで確かめたことは [log-check-2026-11-08.md](log-check-2026-11-08.md)。

## 全体の形

.NET 10（LTS）。Windows でしか要らないもの（写真の監視、インストーラー、トレイ。トレイは WinUI 3 と一緒に作り、まだない）以外は OS に依らず書き、サーバーの役は Linux でも動かす。

```
src/
  Yamaori.Core/      ログの行の読み方、訪問・出会いの組み立て、時刻の直し方（OS に依らない、外のものに頼らない）
  Yamaori.Store/     SQLite（Microsoft.Data.Sqlite）。表の作成と版の上げ方、記録の読み書き、VAT・VRCX の取り込み
  Yamaori/           常駐プログラム（Generic Host）。ログの見張り・生のログの保存・写真・API・WebUI を載せる
web/                 WebUI
extension/           ブラウザの拡張機能
tests/               xUnit。実際のログから作った小さな見本（名前と ID は置き換える）で確かめる
```

読み方は 2 段に分ける。

1. **行 → 出来事**: 1 行を「入った」「人が来た」「動画」などの出来事にする。出来事は「どのログの何バイト目か」を持ち、同じ行を 2 度入れない。出来事はそのまま `log_events` に残す
2. **出来事 → 記録**: 出来事を順に流して `visits`・`encounters`・`people`・`events` を作る。読み方を直したら、この段だけ全部やり直せる（生のログからは段 1 からやり直せる）

- メモ・日記（Markdown）を訪問・ワールド・人・日に付ける

- 見せ方（設定で選ぶ）:
  - 既定: `localhost` だけで待つ
  - 家の中から: 同じネットワークの端末から見られるようにする。認証を有効にする
  - Tailscale: `tailscale serve` 越しに見る。`tailscale serve` から来た要求は localhost から来たように見えるので、Tailscale が付ける本人の情報（`Tailscale-User-Login`）で、許した人だけを通す。この見分けは Tailscale を使う設定にしたときだけ信じる

- WebUI は Svelte 5＋TypeScript＋Vite で作り、ビルドした静的なファイルを常駐プログラムに埋め込む。仮想 DOM の実行部分がなく軽い。部品と型で直しやすく保つ。API の型は OpenAPI から作る（openapi-typescript）

- VRCX の DB（`%AppData%\VRCX\VRCX.sqlite3`。読むだけ。入っていれば使う）。to-fu には入っていないので、VRCX のソース（vrcx-team/VRCX の `src/services/database/index.js`）の表の定義で見本を作って確かめる。表と取れるもの（2026-11-08 にソースで確かめた）:

  - `<userId>_friend_log_history`（フレンドの増減・表示名の変更・信頼のランクの変化と時刻）、`<userId>_friend_log_current`（今のフレンド）: ログでは取れない
  - `<userId>_notifications`・`_notifications_v2`（招待・フレンド申請など。招待先のワールド名つき）
  - `cache_world`（名前・作者の ID と名前・説明・画像とサムネの URL・公開の状態・作成と更新の日時・版）: VRCX の**ローカルのお気に入りに入れたワールドだけ**が書かれる（`favoriteCoordinator.js`・`worldCoordinator.js`）。行ったワールド全部ではない

- CSV（Notion の Worlds DB など）
- ログの記録と取り込んだ記録が重なる期間は、ログを正とする

## 決めたこと（2026-11-08）

1. **開発の環境**: .NET 10 の SDK を、この Linux の PC（`~/.dotnet`）と to-fu に入れた。段階 1〜3 は Linux で書いて試し、to-fu では実際のログで動かして確かめる
2. **WebUI**: 軽く、直しやすさも保つ。Svelte 5＋TypeScript＋Vite で作る。API を先に固めるので、合わなければ作り直せる
3. **写真**: 大半は NAS に移している。段階 4 で NAS の写真も読む
4. **拡張機能でどこまで取るか**: 既定は「押したときだけ今のページを保存」（規約との関係の 2）。「開いたページから自動で読む」（3）と「タブをまとめて開いて取る」（4）は、それぞれ本人が設定で有効にしたときだけ。VRCX が入っていれば、その DB を読んで足す
5. **日記・メモ**: 公開するので Obsidian などを前提にせず、単独で足りるようにする。DB に持ち、WebUI で書く・読むのが完結する。ほかのアプリからも REST API で読み書きできる。Markdown へは書き出せる
6. **使い始め**: 段階 2（生のログを残す）を入れたら、to-fu でログオン時に起こして記録を貯め始める
7. **見せ方と認証**: 既定は localhost だけ。家の中から見る設定と、Tailscale（`tailscale serve`）を使う設定を選べる。Tailscale を使わない人のために、Yamaori 自身が認証を持つ。自分で外へ公開する人には、認証を付けるよう強く勧める
8. **複数の端末**: 別の PC でも遊ぶ人のために、記録を 1 か所にまとめられるようにする。どの端末の記録かを残す。サーバーがなくても、本人が決めた端末（デスクトップなど）を親にできる。Quest の単体の分は抜けてよい
9. **複数のアカウントと名前の変更**: 訪問と出来事は、どのアカウントで行ったかを持つ。見分けはログインしたときの行（`post login checks for 名前 (usr_…)`）の本人の ID で行う（名前は変えられるので使わない）。起こしたまま切り替えたら、そこから先は新しいアカウントの記録。人もアカウントも ID で束ね、名前の移り変わり（いつからいつまでその名前だったか）を残す。名前しかない取り込み（VAT）は、その時期に使われていた名前から ID を引き当てる

## レビュー（2026-11-09）

最初の決めごと・今の文書・実物を、Codex（安全、記録を壊さないか）と Fable（仕様と設計）に読み取り専用で見てもらった。直したあと、Codex にもう一度見てもらい（codex-recheck.md）、直しで入った穴（VAT と VRCX の重なりの判定が広すぎた、結び付く前の子のトークンでメモを黙って捨てた、名前だけの人を忘れると同じ名前の別人まで入れなかった、忘れた人へのメモが子から戻った、写真の設定で種類だけ変えると確かめを抜けた、要求ごとに使った時刻を書いていた）も直した。原文は [docs/reviews/2026-11-09/](reviews/2026-11-09/)。

直したもの（それぞれ試験を足した）:

- 認証: パスの大文字小文字で認証を抜けられた（`/API/days`）。トークンに範囲（全部・拡張機能・子の端末）を持たせ、設定・トークン・止めることは本人（ログインした画面・この PC）だけにした。認証なしの公開は読むだけ。Origin は番号まで比べる。接続の試しで置いてある秘密をほかの相手へ送らない。ログインの検証の同時実行を絞った。設定の値を確かめる。メモやフレンドの一覧の量に上限
- 画面と拡張機能: 動画のリンクは http・https だけ。共有の画面は押すまで保存しない。ワールドの画像は VRChat の置き場のものだけ。拡張機能は本人の応答を要る項目に削ってからページへ流し、ページから来た値の形と数を確かめる
- 写真: 消す前に、手元の大きさと送り先にまだあるかを確かめ直す。見張っているフォルダが送り先と同じなら消さない。同じ名前で中身の違う写真を上書きしない
- 記録: ログのフォルダと残すフォルダが同じだと、VRChat の元のログを消していた。DB の書き込みを電源断に強くした。見張りは思わぬ失敗でも止まらない。タイムゾーンが見つからなければ組み立て直さない。子のメモを同じ秒に書くと送り漏れた
- 取り込み: VRCX のメモを直したら次の取り込みで戻さない。前と別の DB の取り込みは `--replace` のときだけ。VAT と VRCX の同じ期間を二重に入れない
- インストーラー: 入れた場所の Yamaori だけを止める。止めるよう頼む番号は yamaori.json のもの
- 公開に向けて: DB の写し（`backup`、版を上げる前の自動の写し、新しい版の DB は古い版で開かない）、人を忘れる、はじめにの案内、README の「何を記録し、どこへ送り、どう消すか」

残したもの（本人の判断か、あとで）:

- メモを消したことは親へ届かない。親と子で時計がずれると、新しい方の直しが捨てられうる（直すなら、親が版を振るか、消した印を送る）
- データのフォルダを写した 2 台の子は、親で同じ端末として互いを上書きする（端末ごとの鍵が要る）
- 同じ通知が 2 本のログにあると、片方だけ読み直したときに消えることがある。`reparse` の消すと入れ直すが 1 回の書き込みではない（生のログから読み直せば戻る）。同じ長さで中身だけ替わったログは気づかない。閉じて固めたあとに元のログが伸びても写さない
- 日をまたぐ訪問は、入った日にだけ数える。日の区切りは親のタイムゾーン（記録した端末のタイムゾーンにするかは本人の判断）
- 子にだけ入るもの（取り込み・拡張機能・スマホの保存）を親へ送るか
- Tailscale のヘッダーは、この PC のプロキシからの要求なら信じる（`tailscale serve` 以外のプロキシをこの PC に置く人には要る対策）
- 設定の置き場所が yamaori.json と DB の 2 か所（起こし直しが要るものは yamaori.json、すぐ効くものは DB）
- 「保存」の一覧の名前が日本語の決まった文字（公開のときに鍵と表示名を分ける）
- CI・CHANGELOG・拡張機能をストアに出すか
- 写真は名前と大きさで見分けるので、同じ名前・同じ大きさで中身の違う写真は 1 枚として扱う（消す前に中身を比べて、違えば消さないところまでは直した。見分けを中身のハッシュにするのは、写真の ID が変わるのであとで）。送り先の写真が同じ大きさの別の中身に替わっていても気づかない
- ログインの失敗が 10 分に 31 回を超えると、外からのログインを全員 5 分止める（この PC からは止めない）
- 子から送られる記録の量は、要求の大きさの上限（30 MB）だけで絞っている。日の一覧は全部の訪問を読んで数える
- 更新の前に作ったトークンは「全部」の範囲のまま（拡張機能に入れたものは、範囲を絞って作り直すとよい）

## 規約との関係

VRChat の利用規約（Effective Date: October 23, 2026、https://hello.vrchat.com/legal ）で、Yamaori に関わる条文。

- 13.2(j): VRChat が出していない「engine, software tool, agent, device, or mechanism」で、Platform に「access, search, or otherwise use」すること、または「to extract data」ことを禁じる（robot・spider・crawler・scraper・その他の自動の手段を含む）。量や、通信を増やすかどうかの区別はない
- 13.2(i): 「harvest, or mine User Content」、「access or use the Platform in a manner inconsistent with individual human usage」を禁じる
- 13.2(g)(iii): 「attempting to collect personal information about another User or third party without consent」を禁じる
- 12: スクリーンショットと動画を撮って共有することは認めている
- コミュニティガイドライン 5.8: VRChat のログイン情報を求めるサービスを作ってはいけない

文面から読める、グレーの度合いの順（法的な判断ではない）:

1. 自分の PC のログと写真を読む: VRChat 自身がログの場所を案内し、写真に XMP を入れている。Platform に触れない。いちばん強い
2. 拡張機能で、本人が押したときに今のページの情報を保存する: スクリーンショットの許可に近いが、「extract data」に当たると読める余地はある
3. 拡張機能が、本人の開いたページのデータを自動で読む（ワールドの情報の 1・2、フレンドの一覧の差）: 通信は増えないが、13.2(j) の「software tool … to extract data」に文面上は当たる。フレンドの一覧は、ほかの人の情報なので 13.2(g)(iii) にも近い
4. 拡張機能がタブをまとめて開いて取る: ページを開くこと自体を道具がするので、自動の手段に近づく。情報を一度に埋める代わりの手段がないので、設定で有効にしたときだけ動かす
5. API を叩く: 13.2(j) に当たる。Yamaori は作らない（VRCX の DB を読むだけにする）

なお、会った人の名前と ID をログから記録すること自体も、13.2(g)(iii) の「ほかの人の情報を集める」に文面上は近い。VRChatActivityTools・VRCX も同じことをしており、記録は本人の手元だけに置く、という立場で扱う。
