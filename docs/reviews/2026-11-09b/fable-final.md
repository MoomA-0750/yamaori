# 食い違いの最終結論（Codex 原文 codex-design.md / codex-code.md を読み、必要な箇所はコードを読み直した）

判断の軸: 「戻せないもの・公開後に契約（スキーマ／同期の形／ID）を変えると移行が要るもの」は今、「表示や規則で後から変えられるもの」は後。規模は変える場所と手順で言う。

## D3 SFTP の鍵 — **確定（TOFU）＋鍵を忘れる条件を絞る**
Codex の弱点指摘（保存のたびに全鍵を消す `Auth.cs:411-413`）はそのとおりで、これを「Kind/Target/Username が変わったときだけ消す」に直せば TOFU の弱さはほぼ消える。「画面で信じるを押す」は、写真の送り出しが本人の確認待ちで止まる手順（設定→保存→戻って確認）を増やし、得られるのは家の LAN で初回接続の瞬間だけの MITM 対策。戻せる同士なので手間の少ない方。あわせて `/api/settings/photos/test` の返事に見えた指紋を入れ、不一致を WebUI に出す（今はログだけ `PhotoWatcher.cs:91-94`）。

## D4 日の区切り — **確定（親のタイムゾーン）**
Codex 案（訪問に local_date と tz を持ち、同期・VAT・VRCX にも通す）はスキーマ＋同期の形＋取り込み 3 本の同時変更で、利点は「旅先の子」だけ。将来やるなら `visits.time_zone`（nullable）を足して同期 JSON に項目を増やすだけで済み、追加だけで互換（System.Text.Json は未知の項目を無視）。今の表示規則は戻せる。

## D5 日またぎ — **確定（入った日）**
分けると「9 日の夜」が 10 日にも出て、日のメモ（`day` の target_id）がどちらに付くかも決め直しになる。訪問の UTC 区間は変えないので、表示規則はいつでも変えられる。Codex の `visit_days` 投影は D13 の集計と一緒にやるなら意味があるが、今は要らない。

## D6 子だけのデータ — **確定（送らない）＋README に手順**
取り込みの出どころが端末を含まない固定文字（`VrcxImport.cs:21`）なので、送るには出どころ名と StableId の体系を変える。親へは拡張機能・スマホが直接送れる。VRCX の DB は「親へ写して import-vrcx --file」と README.md:106 付近に書く。後で足すなら `vrcx:<device>/…` の出どころを追加する形で互換。

## D7 メモ — **変える＝墓石だけ**（親の revision・競合コピーは入れない）
親が振る revision は子が親から取り込む経路（今は一方向 push のみ `SyncWorker.cs`）を要し、同期の形を作り直す。墓石（`notes.deleted_at` の移行 12、`DeleteNote` が立てる、`SyncNote.DeletedAt`、一覧は `deleted_at IS NULL`）は追加だけで古い子とも互換。時計ずれは NTP 前提で残す。

## D8 複製した子 — **確定（README の 1 行）**
Codex 案（OS 保護領域の端末鍵＋親で公開鍵と結び付け）は新しい秘密の管理と親子の手順を増やす。実害は「2 台が 1 台に見える」で、記録は消えない（出どころはログ名を含む `LogProjector.cs:150`）。Windows では DPAPI で写した設定の親トークンが読めず、D18 を直せば「同期できないので入れ直す」で止まる。「子を増やすときはフォルダを写さず、DB を消して起こす」と書く。

## D10 「保存」 — **変える（小、公開前）**
前回「今は確定」としたが撤回。公開後に変えると API の `list: "保存"` を送る iPhone のショートカット・拡張機能のために別名を残す必要が生じ、今なら `saved` を内部キーにして WebUI で表示名に変えるだけ（`Api.cs:53-54`、`Queries.cs:343,351`、既存行の UPDATE 1 本）。利用者が付けた一覧名は表示名のまま。

## D11 写真の ID — **ID は変えない。消す直前に送り先と手元の中身（SHA-256）を比べ、合わなければ消さない**
Codex の「高」は実物どおり: `PhotoSync.cs:47-61` は送り先に同じ大きさがあれば送らず「もうある」と記録し、`86-107` は大きさだけで確かめて消す。ただし VRChat の写真名はミリ秒の時刻と解像度を含むので起きるのは実質「同じ長さに壊れたファイル」だけで、ID を中身のハッシュに変えると NAS の全写真を一度読み直し、送り先のファイル名も変わる（Codex 自身が一方向と認める）。消す操作だけが戻せないので、そこに中身の照合を置く（`IPhotoTarget` に読み出しを 1 つ足し、3 つの送り先で実装。照合できない送り先では消さない）。A/B の片方が目録から外れる場合も同じ照合で止まる。

## D12 全体ロック — **確定**
Codex 案のトークンバケットも、空になれば正規の人を断る点は同じで、違いは「5 分固定」か「流量で回復」か。接続元ごとの指数バックオフは既にある（`Auth.cs:216`）。PBKDF2 の同時数も絞ってある。LAN の攻撃者による締め出しは DoS に留まり、この利用者層で作り込む価値は低い。

## D13 量の上限／日の一覧 — **上限は今（直すもの）、集計は後で**
projection の配列件数・文字列長の上限（`Api.cs:112-120` に 10 行）は害がなく今入れる。days の SQL 集計・ページングは性能の話で、D5 の表示規則と絡むので後。

## D14 Tailscale — **確定＋README の 1 行**（WhoIs はしない）
LocalAPI の WhoIs は tailscaled のソケット／名前付きパイプと認証トークンに依存し、Docker の親では使えない。脅威は「この PC に tailscale serve 以外の loopback プロキシがあり、外のヘッダーを素通しする」構成だけ（Codex も「未確認」）。後で固めるなら専用の第 2 の loopback ポートでだけヘッダーを読む方が小さい。HTTP レベルの試験にヘッダー付きの場合を足す。

## D17 reparse ほか — **reparse の 1 tx だけ直す**（通知の出どころ表・ログの mtime/ハッシュは入れない）
`LogIngestor.cs:32` の Delete を Ingest の tx に入れる（10 行）。通知の消える条件は、所有する出どころそのものが無くなるときだけで、再現経路を見つけられなかった。同じ長さで中身だけ替わるログは、名前が秒まで含むので起きない。

## Codex D18 .gz のあとに伸びたログ — **直すもの（小）**
`LogArchive.cs:23` は gz があれば即 return。閉じる判定は「VRChat のプロセスがない」か「新しいログがある」（`LogWatcher.cs:61`）なので、起きるのは終了直後の遅延書き込みだけだが、直し方は安い: gz の末尾 4 バイト（ISIZE）と元の長さを比べ、元が長ければ作り直す。

## Codex D19 忘れる一覧の配布 — **確定（端末ごと）＋README＋`resync` コマンド**
配るには子が親から取り込む経路が要る（D7 と同じ理由で今はない）。ただし Codex の副次的な指摘は実物どおり: 親で解除しても、子の記録は子のハッシュが変わらないので再送されない（`SyncWorker.cs:56`）。README に「忘れるは端末ごと」「子の記録を戻すには子で `yamaori resync`」と書き、`sync_state` を消すだけの小さなコマンドを足す。

## Codex D20 自動の世代バックアップ — **変える（公開前まで）**
VACUUM INTO は既にある（`Database.cs:54-63`）。日次で DataDir/backups に有限世代（既定 7）、設定で切れる・場所を変えられる。メモは唯一ログから戻らないデータで、この費用（BackgroundService 1 つ）に対して得るものが大きい。同じディスクなので壊れた DB・誤操作からの回復用と README に明記。

## D1 関連（full トークンで子の記録を消せる） — **変える＝`/api/sync/*` を sync 範囲だけに**
Codex の指摘どおり full は `/api/sync/projection` を通り（`Auth.cs:105` で full は素通り）、結び付けの検査は Sync だけ（`Api.cs:115`）なので、漏れた full トークンで子の記録を空にできる。「範囲にかかわらず結び付け必須」より、`Forbidden` に「/api/sync/ は token.Scope == Sync 以外 OutOfScope」を足す方が小さい（ログイン済み・この PC からは asUser で通るまま）。併せて scope 必須化（前回）と、試験に「full/extension/別の sync から既存の出どころを空にする→403・件数不変」を足す。v9 の旧トークンは未公開なので無効化は不要。

## 「設計でなく直すもの」への異論
異論なし。1 点だけ注意: 取り込みとログの重なりを「区間」で見るとき、必ずワールド＋インスタンス＋アカウントも比べること（codex-recheck 5 で「時間の区間だけで飛ばして別ワールドの訪問を捨てた」を直したばかり。区間に戻すと再発する）。
