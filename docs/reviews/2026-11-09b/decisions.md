# Yamaori の設計の判断（2026-11-09 時点、HEAD 221372f）

Yamaori: VRChat のローカルのログから過ごした時間を記録する、Windows に常駐する .NET 10 のアプリ。WebUI は Svelte 5。使うのは基本的に本人 1 人（PC 1〜数台、子→親の同期あり、スマホから見る）。VRChat の API は使わない方針は動かさない。
背景の文書: README.md、docs/plan.md（特に「レビュー（2026-11-09）」の「残したもの」と「規約との関係」）、docs/reviews/2026-11-09/ の前回のレビュー。

各判断について、レビューの結論を「確定（今のまま）」「変える（どう変えるか・変える場所）」「本人にしか決められない（理由）」のどれかで出してほしい。本人は、設計を確定するかどうかをレビューの結論にゆだねている。迷うなら、どちらでも害が小さい・あとで戻せる方に倒し、そう書くこと。

D1. トークンの範囲（本人は推奨どおりで了承済み。覆す強い理由があれば言う）: 全部・拡張機能（とスマホの保存）・子の端末（最初に送ってきた端末に結び付く）の 3 つ。パスワード・トークン・設定・止める・起こし直すは、ログインした画面かこの PC からだけ（トークンでは届かない）。認証なしの公開は読むだけ。更新前に作ったトークンは「全部」のまま。読むだけのトークンは作っていない。
D2. 人を忘れる（了承済み、同上）: 会った記録・出来事・フレンドの記録・その人へのメモを消し、トリガーで以後入れない。生のログには残る。やめられる（メモは戻らない）。ID のない名前だけの記録は、名前で消す。
D3. SFTP の相手の鍵: 初回を信じて覚える（TOFU）。違えばその回は送らず警告。写真の設定を保存し直すと覚え直す。他の案: 指紋を設定に貼る、画面で「信じる」を押す。
D4. 日の区切り: 親のタイムゾーンで区切る。log_files.time_zone は持っているが使っていない。旅先の子の記録がずれる。案: 記録した端末のタイムゾーン。
D5. 日をまたぐ訪問は、入った日にだけ数える。
D6. 子にだけ入るもの（VAT・VRCX の取り込み、拡張機能のワールドの情報とフレンド、スマホの保存）は親へ送らない（README に書いただけ）。送るべきか。
D7. メモを消したことは親へ届かない。親と子で時計がずれると新しい方の直しが捨てられうる。案: 親が版を振る・消した印を送る。
D8. データのフォルダを写した 2 台の子は、親で同じ端末として上書きし合う。案: 端末ごとの鍵。
D9. 設定の置き場所が yamaori.json（起こし直しが要るもの）と DB の settings（すぐ効くもの）の 2 か所。
D10. 「保存」の一覧の名前が日本語の固定の文字（Api.cs）。
D11. 写真は名前と大きさで見分ける（消す前には中身を比べる）。案: 中身のハッシュで見分ける（写真の ID が変わる）。
D12. ログインの失敗が 10 分に 31 回を超えると、外からのログインを全員 5 分止める（この PC からは止めない）。
D13. 子から送られる記録の量は要求の大きさの上限（30 MB）だけで絞る。日の一覧は全部の訪問を読んで数える。
D14. Tailscale のヘッダーは、この PC のプロキシ（loopback）からの要求なら信じる。
D15. 拡張機能をストアに出すか。CI と CHANGELOG を置くか。
D16. GitHub へ上げるか・非公開か（上げる操作は本人の了承が要る。勧めだけでよい）。
D17. reparse の消すと入れ直すが 1 回のトランザクションでない／同じ通知が 2 本のログにあると片方の読み直しで消えうる／同じ長さで中身だけ替わったログに気づかない（どれも生のログから読み直せば戻る）。今のまま残してよいか。

ほかに、文書にも挙がっていないが今決めておくべき設計の判断があれば D18 以降として足してほしい。
