# Yamaori 設計・仕様レビュー（Fable、読み取り専用、2026-11-09）

対象は README・docs/plan.md・Obsidian の Yamaori.md・実物。重い順に並べる。コードの細かい安全とデータの壊れ方は Codex の担当なので、ここでは見ていない。

## 1. API トークンに範囲がなく、子用トークンが管理者権限になっている

- どこ: Auth.cs:40、Access.cs:51（`var authenticated = r.HasValidSession || r.HasValidToken;`）、AuthStore.cs:112-117（ValidToken はハッシュの一致だけを見る）
- トークンは「有効か」しか見ていないので、どのトークンでも次の経路が全部通る。
  - `/api/settings`
  - `/api/settings/shutdown`
  - `/api/auth/tokens`
  - `/api/notes` の削除
  - `/api/sync/projection`
- 子の端末や拡張機能の設定が漏れると、親の記録全体の読み出しと設定の書き換えまで届く。
- `/api/sync/projection` は本文の DeviceId を信じる（SyncStore.cs:92）。そのため 1 つのトークンで、別の子の端末の記録を入れ替えられる（消せる）。
- 勧める直し方: トークンに範囲を持たせる（read・notes・extension・sync・admin）。sync は端末 ID と結び付ける。設定・トークン・止める・起こし直すは、セッションだけに限る。

## 2. 「認証なしで外から見せる」の説明が実態より軽い

- どこ: Settings.svelte:189、Auth.cs:192、Access.cs:79
- 画面の説明は「見られる」としか言っていない。実際には、メモの書き換え、設定の変更、パスワードの設定、トークンの発行、止めることまで通す。
- 勧める直し方: この設定を「読み取りだけ許す」に変える（GET と HEAD 以外は、これまでどおり認証を要る）。

## 3. プライバシーと規約の整理が「自分 1 人・1 台」の前提のまま

- (a) 「記録は手元だけ」は、親と子・サーバーの構成で崩れる。他人の ID と表示名、フレンドの増減、フレンドの一覧の写しが、借りた VPS などへ送られうる。README にはこの性質の説明がない。
- (b) 「VAT・VRCX も同じことをしている」は、正当化として弱い。公開するときは、README に次の 3 つを明記する節が要る。
  - VRChat 公式とは関係がない
  - 規約との関係は、使う人が判断する
  - 他人の情報を含む記録の扱いは、使う人の責任になる
- (c) 「忘れる」手段がない。人やワールドの単位で消す API がない。encounters を消しても、rebuild や reparse で戻ってくる。
- (d) hook.js は `/api/1/auth/user` の応答を丸ごと postMessage でページへ流している。auth/user には本人のメールアドレスなどが入る（未検証）。
- 勧める直し方:
  - README に「何を記録し、どこへ送り、どう消すか」の節を足す。
  - 人の単位の「忘れる」機能を足す。
  - hook.js は、要る項目に削ってから流す。

## 5. 公開に向けて欠けているもの

- **最初の体験:** silent install では何も開かない。記録が 0 件のときの画面は「まだ記録がありません。」だけで、次にすることへの道案内がない。
- **更新と後戻り:** DB の移行は前へ進むだけ。更新する前に DB を写しておけば戻せる。
- **書き出しと持ち出し:** 日記の Markdown しかない。`VACUUM INTO` で写しを作る `backup` のコマンドがあるとよい。
- **消し方:** データの場所と、外すときに記録も消す選択（`/REMOVEDATA`）が、文書にない。
- **壊れたときの戻し方:** rebuild と reparse で戻るのは、ログから作った記録だけ。メモ・拡張機能のワールドの情報・トークンなどの控えの取り方が、文書にない。
- **リリースの土台:** CI・CHANGELOG・商標の確認・拡張機能の配り方が、まだ決まっていない。

## 6. 設計の筋（あとで困る形）

- 子から親へ送るのは、ログの記録とメモだけ。拡張機能のワールドの情報・フレンド・保存・取り込みは届かない。拡張機能の既定の送り先は localhost なので、子の PC で使うと子の DB にだけ入る。そのことが、文書のどこにも書かれていない。
- 日の区切りは、親のタイムゾーンで決まる（Queries.cs:50）。log_files.time_zone を持っているのに使っていない。
- 親と子の役割を、親の側では持っていない。親は、子の端末とトークンの結び付きを知らない。端末を消す手段もない。
- 設定の置き場が、yamaori.json と DB の settings 表の 2 か所に分かれている。
- 画面とやり取りする型（DTO）が、SQLite に依存する Yamaori.Store と、Yamaori.Web に散らばっている。
- 「保存」の一覧の名前が日本語の固定の文字になっている（Api.cs:53）。

## 良くできていて変えなくてよい点

- 入口の判断を純粋関数（AccessPolicy.Decide）に切り出し、試験で場合を網羅している。
- 行 → 出来事 → 記録の二段の形と、log_events・生のログを残すこと。
- StableId で、メモの付け先が動かない。
- トークンとセッションはハッシュだけを持っている。写真を消す前の確かめ。SFTP の鍵のピン留め。
- 管理者権限なしで、silent install ができ、外しても DB が残る。
- 規約を条文の番号つきで段に分け、既定を一番弱い段に置いた整理。
