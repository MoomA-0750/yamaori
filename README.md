# Yamaori

VRChat で過ごした時間を自動で記録し、あとから振り返ったり、メモや日記を書き足したりできる、自分だけの旅の記録のアプリ（for VRChat）。

名前は「山折り」から。旅先で過ごした時間・訪れた場所・会った人・撮った写真を、一枚の紙に折りたたむようにしまっておき、あとで開いて振り返る。

> 作っているところ（2026-11-09）。ログの記録、生のログの保存、WebUI・REST API・SSE・MCP、写真の目録と NAS への送り出し、VRChatActivityTools・VRCX の取り込み、ブラウザの拡張機能、親と子の端末、インストーラーまで。winget への登録は公開のとき。段階の計画は [docs/plan.md](docs/plan.md)。

### 試す

.NET 10 の SDK と Node（画面のビルド）が要る。

```sh
(cd web && npm ci && npm run build)    # 画面を src/Yamaori/wwwroot へ
dotnet test
dotnet run --project src/Yamaori       # 常駐して見張る。http://localhost:47800 を開く
```

- コマンド: `ingest`（ログを一度読んで DB に入れる）・`summary`・`rebuild`（DB の出来事から組み立て直す）・`reparse`（残した生のログから読み直す）・`export --out <dir>`（日記を日ごとの Markdown に）・`import-vat --file <db>`・`import-vrcx [--file <db>]`（前と別の DB を取り込むときは `--replace`）・`backup [--out <file>]`（記録の写し）・`resync`（子の端末で、次の回に全部を親へ送り直す）・`set-password`（パスワードを決める。サーバーやコンテナで）
- ブラウザの拡張機能は [extension/](extension/)
- スマホからワールドを保存する: WebUI をホーム画面に置くと（Android の Chrome。https か localhost のとき）、共有の行き先に Yamaori が出る。vrchat.com のワールドのページを共有すると「保存」の一覧に入る。iPhone は「ショートカット」で、共有シートから「URL の内容を取得」（POST `/api/worlds/save`、本文 `{"url": 共有された URL}`、ヘッダー `Authorization: Bearer <トークン>`。トークンの範囲は「拡張機能・スマホの保存」）を作る
- 引数: `--log-dir`・`--data-dir`・`--database`・`--archive-dir`・`--device-name`・`--port`・`--listen`（`local`・`lan`・`tailscale`）。データのフォルダの `yamaori.json` でも決められる
- API の定義は `/openapi/v1.json`、今の出来事は `/api/stream`（SSE）、AI のエージェント向けは `/mcp`（例: `claude mcp add --transport http yamaori http://localhost:47800/mcp`）
- Windows で開発中の版を入れる: `scripts/install-dev.ps1`（ログオン時に起こす。`-Uninstall` で外す）
- 止める・起こす: 窓もトレイもない。止めるのは WebUI の設定か `POST /api/settings/shutdown`（この PC から）、起こすのはログオン時か `Yamaori.exe`。トレイの窓は WinUI 3 と一緒に作る

## できるようにすること

- **自動の記録**: VRChat のログから、行ったワールド・入った時刻と出た時刻・同じインスタンスにいた人・流れた動画・届いた招待やフレンド申請を記録する
- **写真**: VRChat で撮った写真を訪問とつなぎ、NAS へ送って保管する。NAS の写真を WebUI で見られる
- **ワールドの保存**: ブラウザの拡張機能から、気になったワールド・気に入ったワールドを保存する
- **日記・メモ**: 訪問・ワールド・人・日のどれにでも、Markdown のメモや日記を書き足せる
- **WebUI と API**: 画面を持たない常駐プログラムが WebUI と API を配る。PC とスマホのブラウザから見る。あとで WebUI と同じことができる WinUI 3 のアプリを作る

## 決めていること

### クリーンであること

VRChat の利用規約（13.2(j)）は、VRChat が出していない道具でデータを取ることを、量や通信の多さに関わらず禁じている。そこで、取り方ごとに段を分け、グレーに寄るものは本人が選んだときだけ動かす（詳しくは [docs/plan.md](docs/plan.md) の「規約との関係」）。

- **既定で動くもの**: 自分の PC にある VRChat のログと写真を読む。VRChat の API は使わない
- **既定で動くもの（拡張機能）**: 本人が拡張機能のボタンを押したときだけ、今開いているページの情報を保存する
- **本人が有効にしたときだけ（拡張機能）**: 本人が開いた vrchat.com のページが受け取ったデータを、拡張機能が自動で読む（ワールドの情報、フレンドの一覧の差）。通信は増やさないが、文面上は規約に当たりうる
- **本人が有効にしたときだけ（拡張機能、別の設定）**: 情報のないワールドのページを、本人が押したときにタブでまとめて開いて取る。ページを開くこと自体を道具がするので、いちばん自動に寄る
- **VRCX が入っていれば**: その DB を**読むだけ**で取り込む。VRCX でしか取れないもの（自分が送ったフレンド申請が承諾されたこと、フレンドの増減）はここから
- **しないもの**: Yamaori 自身が VRChat の API を叩くこと、ログイン情報を預かること、本人が押していないのにページを開いて回ること

### 前提にしないもの

- **サーバー**: 1 台の Windows だけで全部動く。サーバーを立てる人は、任意でサーバーに DB と写真を持たせられる
- **AI**: 全機能が AI なしで使える。AI のエージェント（Claude Code など）からは MCP（`/mcp`）で記録を引ける。Yamaori から AI を呼んで分類や日記の下書きをさせるのは、まだ作っていない（段にも入れていない）
- **Visor やほかのアプリ**: 入っていれば API でつなげられるが、なくても困らない
- **VRCX・VRChatActivityTools**: 入っていれば取り込めるが、なくてよい

### プライベートであること

- 記録は本人の手元に置く。外から見られるのは、本人が WebUI を開けると決めた範囲（例: `tailscale serve`）だけ
- そのため、ほかの人の表示名や ID も記録する。SNS や共有の機能は作らない

### 何を記録し、どこへ送り、どう消すか

- **記録するもの**: 行ったワールドと時刻、同じインスタンスにいた人の表示名と ID、流れた動画の URL、届いた招待とフレンド申請、写真の置き場所。拡張機能を有効にしていれば、ワールドの情報とフレンドの一覧の増減。ほかの人の情報を含むので、扱いの責任は使う人にある
- **置き場所**: Windows では `%LOCALAPPDATA%\Yamaori`（`yamaori.sqlite3` が記録、`logs` が VRChat の生のログの写し、`thumbs` が写真の縮小、`yamaori.json` が設定。設定には親のトークンと NAS のパスワードが入る。Windows では本人のアカウントで暗号化し、Linux では平文なので `/data` の権限で守る）。写真そのものは VRChat の写真のフォルダか、本人が決めた NAS
- **外へ送るもの**: 本人が決めたときだけ。子の端末は親へ、ログから作った記録とメモを送る（会った人を含む）。写真は本人が決めた送り先へ。親を借りたサーバー（VPS など）に置くと、ほかの人の表示名と ID もそこに置くことになる
- **消すもの**: 人の画面の「この人を忘れる」で、その人の記録とメモ、その人が受け手の通知、インスタンスの持ち主としての ID を消し、読み直しても入れない（生のログには残る）。忘れるのはその端末の DB だけなので、親と子の両方で忘れる（親で忘れるのをやめたら、子で `yamaori resync` を使うと送り直す）。全部を消すときは、外したあとでデータのフォルダを消す（アンインストールでは記録は残す）
- **控え**: 毎日 1 回、記録の写しをデータのフォルダの `backups` に取り、7 日分を残す（`yamaori.json` の `BackupKeep` で日数、`BackupDir` で場所。同じディスクなので、ディスクの故障に備えるなら別のディスクを指す）。`yamaori backup` でもいつでも写しを作れる（動いている間でもよい）。版を上げるときは、上げる前の写しを `yamaori.sqlite3.bak-v<版>` に自動で残す。戻すときは Yamaori を止めて、`yamaori.sqlite3` を写しに置き換える
- **組み立て直せるもの・直せないもの**: ログから作った記録は、残した生のログから `reparse` で組み立て直せる。メモ・拡張機能のワールドの情報・フレンドの記録・写真を送った記録・トークンはログからは戻らないので、控えを取る
- VRChat 公式とは関係がない。規約との関係は [docs/plan.md](docs/plan.md) の「規約との関係」に整理したが、法的な判断ではなく、使うかどうかは使う人が決める

### 配り方

- MIT で公開する
- インストーラーを作り、winget でも配る。**silent install に完全に対応する**（途中で何も聞かない。設定は引数か後から WebUI で）
- 管理者権限なしで入れられる形を基本にする。常駐プログラムは本人のアカウントで動く（Windows のサービスにすると、本人のフォルダのログや写真が読みにくいため）

## 形

```
[Windows]                                   [任意のサーバー]
 yamaori（常駐・本人のアカウント）              yamaori server
  ├ ログを読む（output_log_*.txt）              ├ DB
  ├ 生のログを写して残す                         ├ 写真（NAS）
  ├ 写真を見つけて NAS へ送る                    └ WebUI・API
  ├ VRCX・VRChatActivityTools を読む（あれば）
  ├ DB（1 台だけで動かすとき）
  └ WebUI・API・SSE・MCP          ──送る──▶  （サーバーを使うとき）
       ▲
 ブラウザの拡張機能（ワールドの保存）
```

- 1 つのプログラムが「集める」「持つ・配る」の両方の役を持つ。1 台だけのときは両方を持つ
- 端末が複数あるときは、本人が決めた 1 台を「親」にする。親が DB を持って WebUI・API を配り、ほかの端末（子）は集めて親へ送るだけになる。サーバーがなくても、デスクトップを親にしてノートを子にできる。サーバーを持つ人は、サーバーを親にできる
- 記録は全部、どの端末のものかを持つ
- 親へ送る記録は 1 件ずつ ID を持ち、二重に入らない。親につながらない間は手元に溜めて、つながったら送る
- 言語は .NET（C#）。サーバーは Linux でも動く。WinUI 3 のアプリは、WebUI と同じく OpenAPI の定義から型を作って API で話す
- 時刻は UTC で持つ（ログの時刻はタイムゾーンのないローカル時刻なので、読むときに直す）

### 端末のグループ

- 1 台を「まとめ役」にしてグループを作る（設定の「端末のグループ」）。まとめ役は記録を全部持ち、画面を配る。いつも動いている PC や NAS（TrueNAS のアプリ）に向く
- ほかの端末は、まとめ役で作った招待の合言葉（一度きり・30 分）と、まとめ役のアドレスを入れて入る。Tailscale があれば、同じアカウントの Yamaori を「探す」で見つけられる
- 端末ごとの役（ログを集める・写真を扱う・VRCX と連携する）は、まとめ役の画面で決める。メンバーは記録を送るたびに自分の役を読み直す
- VRChatActivityTools からの移行と VRCX の取り込みは、設定の「取り込み」から。メンバーの端末で選んだ DB は、まとめ役へ送ってまとめ役で取り込む

### Linux のサーバーを親にする

```sh
docker compose up -d --build
docker compose exec yamaori yamaori set-password --data-dir /data
```

- `http://<サーバー>:47800` を開いてログインし、設定で範囲が「子の端末」のトークンを作る。子の端末（Windows）の設定に、親のアドレスとそのトークンを入れると、10 分ごとに記録とメモ（子で消したメモも）が送られる。親は子と同じか新しい版にする（親が古いと、子は新しい分を送らずに記録のファイルへ書く）
- 子を増やすときは、データのフォルダを写さない（端末の ID が DB に入っているので、写すと 2 台が 1 台に見える。新しい子は空のデータのフォルダで起こす）
- 子から親へ届くのは、ログから作った記録とメモだけ。VAT・VRCX の取り込み、拡張機能で取ったワールドの情報とフレンドの記録、スマホの「保存」、写真は届かない（子の端末の WebUI にだけ出る）。拡張機能とスマホの保存は、親のアドレスと「拡張機能・スマホの保存」の範囲のトークンを入れて、親へ直接送る
- VRCX の DB は Windows の子にしかない。親で取り込むなら、`VRCX.sqlite3` を親へ写して `yamaori import-vrcx --file <写したファイル>`（VAT も同じ）
- 日の区切りは、親のタイムゾーンで決まる（コンテナでは `TZ`）。日をまたぐ訪問は、入った日に数える
- サーバーには VRChat のログがないので、ログの見張りはしない。写真を目録に入れるなら、NAS をつないだフォルダを `/photos` に読むだけで渡す（[compose.yaml](compose.yaml) の注釈を外す）
- 家の外から見るなら、Tailscale などを通し、パスワードかトークンを必ず使う
- 見せ方を `tailscale` にしたときは、この PC に `tailscale serve` 以外のプロキシを置かない（この PC のプロキシから来た `Tailscale-User-Login` を本人として信じるため）

## 記録するもの

| 表 | 中身 |
|---|---|
| worlds | ワールド ID、名前、作者、対応機種、人数の上限、タグ、説明、サムネ、自分で付ける分類（Type・Essential Assets）、お気に入り、行きたい |
| visits | どのインスタンス（番号・種類・地域）に何時に入り、何時に出たか |
| encounters | 訪問ごとに、だれが何時に来て何時に去ったか |
| people | 会った人（初めて会った訪問、フレンドの増減、表示名の移り変わり）。ID で束ねるので、名前を変えた人も同じ人 |
| accounts | 自分が遊んだアカウント（複数のアカウントで遊ぶ人のため）。訪問と出来事はどのアカウントで行ったかを持つ |
| devices | 記録を集めた端末。訪問と出来事はどの端末のものかを持つ |
| events | 動画の URL、招待・リクエスト招待・フレンド申請の送受信と承諾、アバターの変更など |
| photos | 写真の場所（NAS 上も）、撮った時刻、ワールド、どの訪問で撮ったか |
| notes | 訪問・ワールド・人・日のどれかに付く Markdown のメモ・日記 |

## ログから取れること

VRCX と VRChatActivityTools のソースで調べ、2026-11-08 に実際のログで確かめた（[docs/log-check-2026-11-08.md](docs/log-check-2026-11-08.md)）。

- 入った（`Joining wrld_…:インスタンス`、`Entering Room: 名前`）
- 出た（`OnLeftRoom`、移動の開始の `Destination fetching`、終了の `OnApplicationQuit`。終了の行がないときはログの最後の行の時刻）。起動オプションなしで出る
- 本人の名前と ID（`Preforming post login checks for 名前 (usr_…)`。`User Authenticated` は今は出ない）
- 人の出入り（`OnPlayerJoined` / `OnPlayerLeft 名前 (usr_…)`）
- 動画の URL（`[Video Playback] Attempting to resolve URL` など。流した人の名前は一部のプレイヤーだけ）
- スクリーンショットの時刻とパス（`[VRC Camera] Took screenshot to: …`。Multi Layer カメラの撮影は出ない）
- アバターの変更（名前だけで、ID は出ない）
- 招待・フレンド申請の通知（`Received Notification`。同じ通知が何度も出るので ID で重ねない。フレンド申請は確かめた。招待と、自分が送った・承諾した行はまだ確かめていない）
- **取れないもの**: 自分の送ったフレンド申請が承諾されたこと（VRCX があればその `friend_log_history` から）
- **VRChat は起動したときに 24 時間より古いログを消す**。だから常駐して読み、生のログも別の場所（NAS など）へ写して残す。読み方を増やしたら、残した生のログから読み直せる

写真には、VRChat 2025.3.1 以降、撮った人の ID とワールドの ID が XMP で入っている。写っている人は入っていないので、撮った時刻にその場にいた人で代える。

## ワールドの情報

アプリ本体は VRChat のサイトに取りに行かない。ブラウザの拡張機能が、本人が開いたページから取る。

1. **押して保存**（既定）: vrchat.com のワールドのページで拡張機能のボタンを押すと、そのワールドの情報を保存する。お気に入りや検索結果の一覧のページで押すと、並んだワールドをまとめて保存する
2. **見たページから自動で**（本人が有効にしたときだけ）: ワールドのページや一覧のページを開くと、ページ自身が取ってきたデータを拡張機能が横で読んで送る。通信を増やさず、画面の文字より正確。フレンドの一覧のページでは、前に見た一覧と比べて増えた人・減った人を記録する（時刻は「前に開いたときから今回までの間」と粗い）
3. **まとめて開く**（本人が有効にしたときだけ。2 とは別の設定）: WebUI の「情報のないワールド」から、拡張機能が最大 20 件ずつタブで開いて取り、閉じる。本人が押したときだけ、間隔を空けて動く。止めるボタンと、1 日の件数の上限を付ける
4. **VRCX から**: VRCX のローカルのお気に入りに入れたワールドの名前・作者・説明・サムネ（`favorite_world`・`cache_world`。行ったワールド全部ではなく、タグ・人数の上限・対応機種もない）、フレンドの増減（`*_friend_log_history`）

AI を使わなくても、説明文に出てくる言葉（YamaPlayer、QV Pen など）から Essential Assets を付けるといった分類は、決まりで行う。

## 写真

- 送り先: フォルダ（SMB の共有 `\\NAS\…` や割り当てたドライブ）・SFTP・WebDAV
- 送ったあと手元を: 消す／N 日残す／全部残す、を設定で選ぶ
- NAS の写真を縮小して WebUI で見せる。一覧の縮小は前もって作る（夜の時間帯と、設定の「今すぐ全部作る」）
- NAS から写真を読むのは遅いので、NAS の上で縮小を作れる。設定の「写真の縮小 → NAS の上で作る」で NAS のアドレス・ユーザー・写真のフォルダの組を入れ、Yamaori が作った公開鍵を NAS のユーザーに登録すると、Yamaori が SSH で入って `yamaori-thumbs.py`（Python 3 と Pillow。TrueNAS SCALE には入っている）を動かす。縮小は写真のフォルダの `.yamaori/thumbs` にでき、Yamaori は写真を読まずにそれを使う
- 写真はワールドごと・その場にいた人ごと・アルバムで見られる。ゴミ箱に入れると隠れ（戻せる）、「空にする」でファイルを消す
- メタデータのない昔の写真にも、ワールド・撮った人・一緒にいた人を付けられる（撮った時刻の記録から当てる）。Yamaori の中だけで持つか、写真のファイル（PNG）に VRChat と同じ形の XMP で書く
- TrueNAS のアプリとしても動かせる（[deploy/truenas/yamaori.yaml](deploy/truenas/yamaori.yaml)）。NAS の上で親として WebUI を配り、作った縮小を写真のフォルダにも置くので、ほかの端末の Yamaori もそれを使う
- メディアサーバー（Plex・Immich・Jellyfin など）とのつなぎは後で

## 取り込み

- VRChatActivityTools の DB（`ActivityLogs`。出た時刻はないが、過去の入室・会った人・動画・招待・フレンド申請がある）
- VRCX の DB（`%AppData%\VRCX\VRCX.sqlite3`。`gamelog_*`、`*_friend_log_history`、`favorite_world`＋`cache_world`、`world_memos`）。読むだけ
- Notion などの既存のワールドのメモ（CSV など、一般的な形で）は、まだ作っていない

## 外から使う口

- REST API と OpenAPI の定義（WinUI 3 や他のアプリのクライアントはここから作る。WebUI の型もここから作っている）
- SSE: 今の出来事（入った・人が来た・写真を撮った）を流す
